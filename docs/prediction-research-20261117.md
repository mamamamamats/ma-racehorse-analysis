# 予想方式の改善研究（2026-11-17）

今回は調査・提案のみ。採点式・重み・保存済み予想を変更しない。UIの変更は既存週間結果カードのホームへの移動と縮小だけ。

## 現在の方式

`shared-prediction-engine.js` と `shared-prediction-runtime.js` を確認。S=6、A=4、B=3、C=2、D=0、Fは除外。全体・競馬場・距離・馬場・近走・ラップの加重平均が基礎点。不明な軸は除いて残る重みで割り直す。競馬場・距離・馬場の3走以上かつ平均3点以上を満たす馬には追加ボーナスがあり、その条件を満たす馬が出走メンバー中1頭だけの場合はさらに加点する。

標準重み3で、高適性加点と単独高適性加点は1軸最大2.1点、3軸で最大6.3点。基礎点の上限6点に対して大きい。同じ過去3走が複数軸の根拠になる場合もある。「単独」は能力そのものではなく、出走メンバー内の既知データの構成にも依存する。

競馬場・距離の適性は当該芝ダート内の単純平均。馬場評価は重・不良を共通扱いにする。クラスはラップの比較対象選びには使うが、S/A/B/C/Dの点数自体のクラス補正はない。脚質は表示・保存されるが6要素の採点には入っていない。新しいZスコアによるペース分類も現在の採点には入っていない。

ラップ適性は予測される前傾・後傾・平均型と同じ構成で走った過去走の評価平均であり、「速いペースへの耐性」「同クラスより優秀な絶対ラップ」を直接評価しているものではない。

## 優先する検証

### 1. 近走の定義と少数データの扱い

現在の近走は元配列の先頭3走。先日の開催日順整理は表示だけなので、後から古い回顧を先頭に追加すると、近走の採点は実際の日付順と一致しない可能性がある。日付が確定した走は対象レース以前で並べ、日付不明分の扱いを別に決める。過去表示の整列と、採点式の変更は別版として検証する。

1走だけのS=6と多数走での平均6が基礎点では同じ強さになる。全体や近い条件の平均へ寄せる「少数例の補正」と、未評価の不確実性を比較候補にする。未評価を0点とするのは避ける。

### 2. 適性の二重評価とボーナスの強さ

競馬場・距離・馬場は基礎点にも含まれ、条件加点でも再評価される。検証候補は現状、加点半分、単独高適性加点なし、加点なし程度に絞る。同じレース・馬・評価データで比較し、次週以降の未使用データで確認する。対戦馬のデータ欠損が多いレースで単独高適性を強く評価しすぎていないかも見る。

### 3. S/A/B/C/Dの意味をレース水準と結びつける

新馬・未勝利でのSと上級条件でのAを同じ絶対能力として比べてよいか、という問題。クラスだけで機械的に大きく減点せず、リンク済みレースから「クラス・ペース負荷・レース水準」を補助情報として検証する。昔のSを一括で書き換えない。元の評価と補正値を別に持つ。

### 4. 追加ファクターの第一候補は「ペース × 脚質」

脚質・位置取り・ペース・ラップ構成の既存データを使える。逃げ先行馬の頭数、同型の多さ、コースの傾向から展開の仮説を作り、各馬の過去評価との相性を調べる。ハイ・ミドル・スローと前傾・後傾は別の軸として扱う。ただし現時点ではペース基準も疎で、まず分析用の補助値として蓄積し、十分な件数ができてから採点へ追加する。

距離も完全一致だけでなく、近い距離とコース形態から段階的に集約する候補がある。未知のコース特性を勝手に補完せず、確かな情報だけ使う。

### 5. 休み明け・間隔、斤量、オッズはデータ整備後

回顧の記録間隔は、実際の出走間隔とは限らない。未回顧のレースがある状態で休み明けと決めつけない。斤量・騎手・馬体重・オッズも現在あると仮定しない。これらを使うなら新規の記録項目と取得方法が必要。オッズは能力点そのものより、確率へ校正した点数と比較する期待値分析に使うのが自然。

## 実験の進め方

評価データと予想設定を固定して、候補ごとに変更する部分を1つに絞る。時系列で過去週を研究、次の未使用週を検証に使い、同レース内の全馬を同じ側へ置く。未来の回顧・最新基準・現在の馬評価を当時の予想へ混ぜない。40R程度で条件を細分化して最適化しすぎない。

最初は「近走の開催日整合」「少数例補正」「適性ボーナスの比較」を行い、その後にクラス水準とペース×脚質を進める案を推奨する。今回の調査で勝てる方式が判明した、という結論ではない。
