# 予想・検証データの公開JSON

馬の全履歴は従来の `keiba-data.json.zip`、予想・結果・全体回顧・開催情報・好走馬の位置取りは `prediction-data/` に分離します。Firestoreが正本です。採点式と保存済み予想は変更しません。

通常の閲覧は月別JSONをキャッシュし、書き出し開始時刻以降の `archiveUpdatedAt` の差分だけFirestoreから取得します。編集中の保存にもサーバー時刻を付与します。削除は記録を照合します。公開JSONが利用できない場合は従来のDB読み込みへ戻ります。分析画面の「DBの最新データを全件取得」はJSONを使わず明示的に最新DBを読み込みます。

古いブラウザーなどタイムスタンプを付けない旧クライアントからの更新・トランザクション内の直接削除は、次回のJSON更新または明示的な全件取得で反映します。公開JSONは既存の馬・開催日の端末保存内容を上書きしません。公開済みSNS用レポートの単一メタデータ取得は即時更新を優先します。

通常の「集計を更新」・ペース基準の再取得は公開JSONを再利用し、差分だけ照会します（refresh）。全件取得（fresh）は分析画面の明示的な全件取得などに限定します。DB差分が上限超過で失敗した場合は警告付きで公開JSONを表示し、このプロバイダーのDB読み取り再試行を5分間抑制します。公開JSONがない場合や権限エラーは、編集モードではエラーを隠しません。

ペース再判定の保存前には、保存対象件数と最低読み取り・書き込み数の目安を表示します。ラップを解釈できず、以前の有効な自動判定もない回顧は書き込みません。上限エラーが出た場合は残りを中止します。これは利用量メーターではなく、他端末・定期書き出し・調査・再試行分は含みません。

## 定期更新

既存の馬データ更新を行った後、その新しいマスターを再利用します。

```sh
node scripts/export-prediction-data.mjs --master-json /tmp/keiba-data.json
# または --master-zip /tmp/keiba-data.json.zip
```

公開Firestore RESTをページ分割で読み取るだけで、DBには書き込みません。馬データを指定すれば全馬の二重取得を避けます。月別の内容ハッシュ付きJSONとmanifestを生成し、変更のない月は同じファイルを再利用します。変更時は直前世代も保持し、それ以前の生成ファイルだけ掃除します。前回より20%以上減るコレクションがある場合は停止するので、原因を確認してください。安易に `--allow-shrink` を付けないでください。

`keiba-data.json.zip` と `prediction-data/**` の変更だけを公開し、変更がなければコミット不要です。manifestの件数・各ファイルのSHA-256、GitHub Pages反映を確認します。

これは閲覧ごとのDB全件取得を削減する仕組みです。定期書き出し時のDB読み取りと差分読み取りは残り、料金が必ずゼロになるものではありません。


## ラップから不足分類を補完

1900mは950mずつ、1150mは575mずつの等距離に分割し、境界区間は距離比例で按分します。未登録のラップ構成（前傾・平均型・後傾）は実数ラップから補完できます。ペースは同条件・クラス区分で自身を除く最低5件との比較です。既存の有効な分類は不足補完で置き換えず、枠・不利は推測しません。

表示用の補完は読み取り専用です。編集画面の「ペース基準・過去判定を更新」→「未分類だけを補完プレビュー」→保存で不足分だけ永続化できます。保存前に件数・読み書き目安を確認してください。新規の全体回顧JSON登録時にも同じ補完を適用します。

管理用スクリプトは最初にプレビューとバックアップを作り、適用時は明示的な件数上限とサーバーupdateTime前提条件を使います。上限・競合エラーは再試行せず停止します。

```sh
node scripts/fill-missing-race-classifications.mjs --backup-dir /tmp/classification-backup
node scripts/fill-missing-race-classifications.mjs --apply --input /tmp/classification-backup/snapshot.json --backup-dir /tmp/classification-backup --max-writes 2000
```

回顧のみを新しく公開する場合、再取得したライブスナップショットを `scripts/publish-review-archive.mjs` に渡します。manifestのcollectionStartedAt.raceReviewsだけを進め、馬・予想・結果など他のコレクションの差分取得開始点は維持します。古い馬マスターを新しい取得時刻として扱いません。
