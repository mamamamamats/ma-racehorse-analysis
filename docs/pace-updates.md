# アプリ内ラップによるペース再判定

公式データを初期基準にする案は廃止。既存回顧本文のラップ（従来と同等の候補抽出・区間数/値域/走破時計確認）を使用する。公式照合済みとは扱わない。前傾・後傾と採点式は変更しない。

## 操作

編集モード → 分析 → **ペース基準・過去判定を更新**。

1. 必要なら「最新回顧をDBから取得」。通常は既存JSONと差分を使う。
2. 条件別の件数・平均・標本標準偏差・対象期間を確認。最低基準件数は初期値5、端末ごとに保存する。暫定閾値はZ±0.7。
3. 「過去レースの再判定をプレビュー」。初期・前回・今回・判定不能理由・履歴を表示。ここまではDBに書かない。
4. 「更新前の回顧をJSONで保存」で対象の控えを取得できる。
5. 「プレビューした判定を保存」で対象回顧だけ更新。プレビュー後に別編集があったレースは保存せず、再取得を求める。失敗分は再取得・プレビューで再試行可能。

全体回顧JSON一括登録でも、本文とともにevents.pace:nullを指定すればプレビュー時点の固定基準で自動判定する。手動値は維持。空テンプレートは従来どおり登録しない。今回の新規バッチのレースを相互に基準へ追加しない。保存が成功した回顧は次回の基準集計対象になる。

## 保存と履歴

raceReviews内の追加フィールド `paceAnalysis` に初回更新前の判定、最新判定と根拠、判定変化の直近20回、総変化回数を保存。初回判定は履歴の間引き後も保持。`history` は日時・from/to・基準版・判定不能理由のみで、基準の詳細を毎回複製しない。同じデータ・設定で再実行しても更新しない。既存手動paceはevents.paceに維持し、自動の最新分析と区別する。

自動管理しているevents.paceは最新判定に更新し、paceMetaに根拠を保存する。元の判定はpaceAnalysis.initialに残る。手動入力はpaceMeta.source=manualとし、再判定による上書きを防ぐ。旧記録の有効なpaceは手動扱いにする。一般/編集モードの既存表示は共通の保存済みevents.paceを参照する。

初回の控えは「機能導入後の初回更新前」であり、過去に実際に登録した時刻の完全な復元ではない。過去の予想スコアや馬評価は再計算/書き換えしない。厳密な当時基準での検証と、今回の最新基準による再評価を混同しない。

基準は回顧キャッシュから必要時に集計する派生データで、全馬を取得しない。永続化は各レースの判定根拠・基準版に行う。回顧が増えれば次のプレビューで基準を再構築する。公開JSONの既存エクスポートが追加フィールドも保持するため定期更新タスクの変更は不要。

## 条件と統計

競馬場・芝ダート・実距離・馬場・クラス・コース形態・改修世代・前半距離が一致するレースだけを使用。重賞はG1〜G3、OPはLを含む。形態/世代未記録は独立した参考区分にし、既知区分と混合しない（未記録同士の改修前後分離は情報不足でできない）。障害・条件不明・ラップ不足・計測境界不一致は判定不能。

日付・競馬場・R番号で重複除去し、訂正ラップは新しい記録で置換する。Welford法でn/mean/M2を計算し、標本標準偏差を利用。各レース判定時は自身の寄与を統計量から取り除くので、全条件の再集計をレースごとに繰り返さない。標準偏差0・基準不足では判定不能。平均値の単純平均、他条件の流用、区間の按分は行わない。

実データ確認：開発時点のローカル公開回顧176件中、有効サンプル121R・83条件。自身を除いて最低5件を満たす条件はなく、現在は判定不能になる。件数不足を埋める架空の基準は作成していない。

## 保護・復旧

既存IDB・マスターJSON優先順位・馬/開催/予想データは変更しない。プレビュー保存はraceReviewsのpace関連フィールドのみマージ。自動更新用archiveUpdatedAtは既存アダプターが付与する。本文の更新日時は変えず、基準の重複採用順がメタデータ保存で揺れないようにする。

不適切な再判定は更新前JSONとpaceAnalysis.initialを参照して、pace関連フィールドだけ復元できる。本文や別の人の編集を丸ごと上書きしない。UIに無条件のDB全体復元は追加しない。新スクリプトを外す場合も追加フィールドは既存機能を壊さず残せる。
